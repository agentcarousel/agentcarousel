## Root Cause

The test calls the live Stripe API (`https://api.stripe.com/v1/charges`) but the CI runner is launched with `--network=none`, which blocks all outbound TCP connections. The request never reaches Stripe and the 5-second Jest timeout fires instead.

This never reproduces locally because your development machine has unrestricted network access.

## Why CI Differs From Local

| Environment | Network | Result |
|-------------|---------|--------|
| Local dev | Unrestricted | Request succeeds in ~200ms |
| CI runner | `--network=none` | Connection refused immediately, test waits for timeout |

## Recommended Fix

**Option 1 — Mock the Stripe client (preferred)**

Replace the live HTTP call with a Jest mock so the test never touches the network:

```python
# payments.test.py
from unittest.mock import patch, MagicMock

@patch('stripe.Charge.create')
def test_charge_success(mock_create):
    mock_create.return_value = MagicMock(id='ch_test_123', status='succeeded')
    result = PaymentGateway().charge(amount=1000, currency='usd', source='tok_visa')
    assert result.status == 'succeeded'
```

**Option 2 — Skip on CI with an environment flag**

```python
import os, pytest

@pytest.mark.skipif(os.getenv('CI') == 'true', reason='no network in CI')
def test_live_charge():
    ...
```

Move live integration tests to a separate suite that runs in a network-enabled environment (e.g., a nightly job with `--network=bridge`).

## Next Steps

1. Audit all `tests/integration/` tests for direct network calls.
2. Apply mocks or a `@requires_network` marker to each.
3. Configure CI to run unit tests with `--network=none` and integration tests in a permissive network context.
