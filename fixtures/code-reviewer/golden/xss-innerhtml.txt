## Security Finding: Reflected XSS via innerHTML

**Severity:** CRITICAL (CWE-79 — Improper Neutralisation of Input During Web Page Generation)
**Affected lines:** +7–9 (`welcome.js`)

### What's Wrong

`document.getElementById('greeting').innerHTML` is assigned a template literal containing `name`, which is read directly from `window.location.search`. An attacker can craft a URL like:

```
https://example.com/welcome?name=<img src=x onerror=alert(document.cookie)>
```

The browser will execute the injected script in the context of the page, allowing session hijacking, credential theft, or DOM manipulation.

### Safe Fix

Replace `innerHTML` with `textContent`. It treats the value as plain text and never parses it as HTML:

```js
const params = new URLSearchParams(window.location.search);
const name = params.get('name') ?? '';
document.getElementById('greeting').textContent = `Welcome, ${name}!`;
```

If rich HTML is genuinely required, sanitise first with DOMPurify:

```js
import DOMPurify from 'dompurify';
document.getElementById('greeting').innerHTML = DOMPurify.sanitize(`Welcome, ${name}!`);
```

### Additional Recommendation

Validate and restrict the `name` parameter at the server side before it reaches the client. Consider a Content Security Policy (`script-src 'self'`) as a defence-in-depth measure.
